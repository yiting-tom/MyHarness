## Why

`inspect --html` 是給**開發者**看的：transcript、token 帳、估計誤差。
它假設讀的人知道什麼是 dispatch、什麼是 `budget_exceeded`。

**但這套 harness 最需要被說服的人不是開發者，是把資料交出去的那個人。**

這個專案的整個架構 —— 原始資料永遠不進上層 context、lane 只讀被授權的東西、
授權邊與讀取邊分開記 —— 全部都是為了讓「我的資料去了哪裡」有答案。
而今天**那個答案只存在於一個終端機指令裡**，而且輸出長這樣：

```
d1 · analyst1  [budget_exceeded]
  └─ ←授權 ▣ raw/txn-2024 138,773B
```

交出資料的人看不懂這一行，也不該要他看懂。他要問的是三件事：

1. **我給的資料，誰看過？** 有沒有哪一份根本沒被用到？
2. **這份報告是根據什麼寫出來的？** 有沒有哪一段其實沒有根據？
3. **有什麼沒做到？** —— 這一項 framework 已經自動蒐集了（`derive_caveats`），
   而它今天只出現在 MCP 回傳的 JSON 裡

golden #24 的 caveats 裡有一句 `budget_exceeded: token 預算耗盡，任務未完成`。
使用者看到的報告裡那段分析是**沒做完**的 —— 這件事值得被放在他看得到的地方，
而不是一個他不會去呼叫的 API 欄位裡。

## What Changes

- **新增 `myharness report <job> [-o out.html]`**：一份給使用者讀的
  **資料來源報告**。資料流是主角，不是側欄。
- **異常與 caveats 一律翻成人話。** `orphan_output` 這個字不會出現在使用者面前；
  「這段分析寫出來了，但沒有被後面的人讀到，也沒有進最終報告」會。
  對照表放在程式碼裡並且有測試，因為它是這個 change 的**內容**而不是措辭。
- **來源鏈預設就是高亮的。** 使用者開頁的第一眼要看到的是「這份報告來自這條路」，
  而不是一張要他自己找路的圖。沒有貢獻的那幾段刻意變淡 —— 那也是資訊。
- **章節仍然先標價再展開**（DESIGN #14）。給人看的時候價目表不是為了省 context，
  是為了讓他知道自己要讀多少。
- **`inspect --html` 不動。** 兩個受眾、兩個視圖；把它們合成一個只會兩邊都不合適。
- **`dataflow` / `events` / `orchestrator` 不動。** 又一個投影。

## Capabilities

### Modified Capabilities
- `monitor`: 新增「給資料提供者的來源報告」的義務。既有需求不變。

## Impact

- **Specs**: `monitor` 新增 4 條需求
- **Code**: 新增 `myharness/monitor/report.py` + `report.html`，
  CLI 新增 `report` 子命令。`delivery.py` 的 `build_delivery` 直接重用 ——
  它已經是對外的交付契約，不需要為了畫面再造一份
- **Deps**: 零新增。一樣是單一自包檔案、不連網
- **風險**：這份檔案含報告全文，而報告是 note 不是 blob —— 它本來就是要交給
  使用者的東西。但它同時含 caveats 與異常，也就是「這次做得不好的地方」。
  **這是刻意的**：把失敗藏起來的透明度報告沒有意義
